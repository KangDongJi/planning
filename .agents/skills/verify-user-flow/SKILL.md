# 사용자 흐름 검증

완료 기준을 실제 사용자 행동과 관찰 가능한 결과로 변환한다. 실행하지 않은 테스트를 통과로 표시하지 않고, 실패는 다른 담당자가 그대로 재현할 수 있게 기록한다.

## 기준 확인

1. 저장소 루트의 `AGENTS.md`를 먼저 읽고 테스트 실행과 수정 권한을 확인한다.
2. `docs/planning/role-structure.md`의 현재 역할 호출명, 테스트 팀장 책임, 인계와 완료 게이트를 확인한다.
3. `docs/development/execution-playbook-design.md` 6절에 따라 프로젝트 식별자 또는 공통, 기준 문서, 대상 작업 경로와 참조 버전 또는 확인일을 식별한다. 목표·범위·요구사항·완료 기준은 `docs/product-planning.md`와 연결된 대상 문서에서 확인한다. 여러 아이디어를 관리하도록 정의된 경우에만 지정된 아이디어 문서와 인덱스를 사용한다.
4. `docs/development/execution-playbook-design.md`의 공통 계약과 PB-05를 확인한다.
5. 실제 실행 전 대상 환경, 필요한 계정·권한, 데이터 조건과 외부 의존성을 확인한다.

## 모드 결정

사용자 요청에서 승인된 범위를 다음처럼 판별한다.

| 모드 | 적용 조건 | 허용 작업 |
|---|---|---|
| 시나리오 | 테스트 실행을 명시하지 않은 검토·QA 요청 | 시나리오, 기대 결과와 통과 기준만 작성 |
| 실행 | "실행해줘", "브라우저에서 테스트해줘"처럼 실제 테스트를 명시 | 승인된 환경과 범위에서 테스트 실행 |
| 실행·수정 | 테스트 실행과 버그 수정을 모두 명시 | 승인 범위 안의 수정과 해당 흐름 재검증 |

- `검증해줘`, `QA 해줘`만으로는 실제 실행 승인으로 간주하지 않는다.
- 테스트 실행 승인을 코드·문서 수정 승인으로 확대하지 않는다.
- 수정 승인 후에도 커밋, 푸시, PR과 배포는 별도 외부 변경 승인으로 다룬다.
- 승인 범위가 불명확하면 시나리오 모드로 진행하고 필요한 승인만 보고한다.

## 시나리오 설계

1. 검증 대상 기능, 사용자 역할, 사전 조건과 완료 기준을 연결한다.
2. 핵심 성공 흐름을 첫 진입부터 최종 결과까지 단계별로 작성한다.
3. 권한 없음, 만료, 빈 상태, 잘못된 입력, 취소, 실패와 복구 흐름을 추가한다.
4. 경계값, 중복 행동, 새로고침, 재시도, 동시 상태와 이전 데이터 영향을 검토한다.
5. 각 시나리오에 관찰 가능한 기대 결과와 필요한 증거를 적는다.
6. 위험과 변경 범위에 따라 단위, 통합, 계약, 회귀, 브라우저, 수동과 보안 검증을 구분한다.

## 실행 절차

실행 모드일 때만 다음 절차를 수행한다.

1. 실행할 시나리오, 명령, 도구와 환경을 먼저 확정한다.
2. 브라우저 흐름은 역할 문서의 `브라우저 작업 도구 선택`을 따른다. `playwright-cli` 스킬과 Playwright CLI를 우선 사용하고, `playwright`는 CLI 래퍼·실행 절차의 보조로 참조한다. 사용자 지정 환경을 우선하며 CLI를 사용할 수 없으면 이유와 대체 도구를 보고한다. 필요한 설치는 기존 승인 범위를 따른다.
3. 테스트 데이터를 실제 민감 정보와 분리하고 외부 변경 가능성을 확인한다.
4. 각 시나리오의 실제 결과와 증거를 기대 결과와 비교한다.
5. 실패에 재현 절차, 실제 결과, 기대 결과, 영향과 증거 위치를 기록한다.
6. 환경 문제와 제품 결함을 구분하고 확인하지 못한 항목은 미검증으로 남긴다.
7. 실행·수정 모드이면 승인 범위 안에서만 수정한 뒤 실패한 흐름과 관련 회귀를 다시 검증한다.
8. 장시간 실행, 비용 발생, 운영 환경 접근 또는 새로운 권한이 필요하면 멈추고 사용자에게 확인한다.

## 출력 형식

역할 문서에서 확인한 현재 호출명을 첫 줄에 표시하고 아래 순서로 작성한다.

1. 검증 모드와 승인 범위
2. 대상 환경·기능·완료 기준
3. 시나리오별 실행 여부와 결과
4. 실패와 재현 조건
5. 수정·재검증 결과
6. 미검증 영역과 잔여 위험
7. 완료 기준 충족 여부와 다음 역할

시나리오는 다음 필드를 사용한다.

| 필드 | 내용 |
|---|---|
| ID | `FLOW-TEST-001` 형식 |
| 관련 기준 | 기능 ID, 개발 작업 ID, 완료 기준 ID |
| 사용자·흐름 | 대상 역할과 행동 |
| 사전 조건 | 환경, 권한, 데이터 상태 |
| 절차 | 재현 가능한 단계 |
| 기대 결과 | 관찰 가능한 결과 |
| 실행 상태 | 미실행, 통과, 실패, 환경 차단, 적용 제외 |
| 증거·리스크 | 로그, 화면, 파일 또는 미검증 영향 |

## 완료 조건

- 실행 여부와 결과 판단을 분리한다.
- 핵심 흐름과 주요 예외·권한 흐름을 포함한다.
- 실패를 재현 가능한 형태로 기록한다.
- 승인되지 않은 실행, 수정과 외부 변경을 수행하지 않는다.
