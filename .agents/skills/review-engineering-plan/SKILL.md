# 기술 계획 검토

구현 전에 숨은 기술 가정과 실패 경로를 드러내고, 승인 가능한 구현 단위와 검증 기준으로 변환한다. 기술 가능성을 이유로 제품 정책을 임의로 확정하지 않는다.

## 기준 확인

1. 저장소 루트의 `AGENTS.md`를 먼저 읽고 작업 권한과 금지 사항을 확인한다.
2. `docs/planning/role-structure.md`의 현재 역할 호출명, 개발 팀장 책임과 착수 게이트를 확인한다.
3. `docs/development/execution-playbook-design.md` 6절에 따라 프로젝트 식별자 또는 공통, 기준 문서, 대상 작업 경로와 참조 버전 또는 확인일을 식별한다. 목표·범위·요구사항·완료 기준은 `docs/product-planning.md`와 연결된 대상 문서에서 확인한다. 여러 아이디어를 관리하도록 정의된 경우에만 지정된 아이디어 문서와 인덱스를 사용한다.
4. `docs/development/execution-playbook-design.md`의 공통 입력·출력 계약과 PB-03을 확인한다.
5. 코드가 있으면 기존 구조, 기술 스택, 구성 파일, 데이터 경계와 테스트 패턴을 읽기 전용으로 확인한다.

## 권한 경계

- 읽기, 검색, 구조 분석과 검토만 수행한다.
- 코드, 스키마, 설정, 의존성과 개발 문서를 생성하거나 변경하지 않는다.
- 빌드, 생성, 마이그레이션과 테스트 명령을 실행하지 않는다.
- 라이브러리, 인프라와 외부 API 도입을 확정하지 않는다.
- 구현이나 실행 요청이 함께 있으면 검토 결과와 착수 조건을 먼저 보고하고 후속 작업으로 인계한다.

## 검토 절차

1. 대상 기능, 입력·출력, 완료 기준과 미정 정책을 연결한다.
2. 현재 구조와 제안 구조의 구성 요소, 책임과 경계를 정리한다.
3. 정상 데이터 흐름과 주요 상태 전이를 단계별로 추적한다.
4. 인증·인가, 공용·전용 데이터, 비밀값과 외부 시스템의 신뢰 경계를 확인한다.
5. 입력 오류, 권한 거부, 외부 연동 실패, 시간 초과, 재시도, 중복 요청과 부분 성공을 검토한다.
6. 데이터 일관성, 보존·삭제, 감사 가능성, 동시성, 성능, 비용과 운영 위험을 검토한다.
7. 기존 패턴과 맞지 않는 선택, 불필요한 추상화와 범위 밖 변경을 찾는다.
8. 작게 구현하고 독립적으로 검증할 수 있는 작업 단위와 의존성을 제안한다.
9. 단위, 통합, 계약, 회귀, 수동과 보안 검증 후보를 완료 기준에 연결한다.
10. `착수 가능`, `결정 후 착수`, `보류` 중 하나로 판단하고 근거를 제시한다.

## 표현 기준

- 구조가 복잡하면 Mermaid 또는 간단한 텍스트 흐름도로 경계를 설명한다.
- 확인한 코드와 문서에 근거한 내용과 제안 설계를 구분한다.
- 기술 선택지는 장점, 단점, 리스크, 되돌리기 비용과 추천 여부를 함께 제시한다.
- 보안이나 최신 외부 정보의 전문 검토가 필요하면 해당 역할 또는 스킬로 인계한다.

## 출력 형식

역할 문서에서 확인한 현재 호출명을 첫 줄에 표시하고 아래 순서로 작성한다.

1. 핵심 기술 판단
2. 확인한 범위와 현재 구조
3. 책임 경계와 데이터·상태 흐름
4. 실패·예외·보안·운영 위험
5. 구현 단위와 의존성
6. 테스트 전략 후보
7. 착수 전 결정 필요 항목
8. 착수 가능 여부와 다음 역할

여러 기술 이슈는 다음 필드를 사용한다.

| 필드 | 내용 |
|---|---|
| ID | `ENGINEERING-001` 형식 |
| 분류 | 필수 보완, 권장 보완, 사용자 결정 필요, 추가 기술 검토, 적용 제외 |
| 관련 기준 | 기능 ID, OPEN ID, 문서 또는 코드 위치 |
| 기술 이슈 | 확인한 내용 |
| 영향 | 보안, 데이터, 운영, 구현, 테스트 영향 |
| 추천 조치 | 구체적인 다음 행동 |
| 착수 가능 여부 | 착수 가능, 결정 후 착수, 보류 |

## 완료 조건

- 정상 흐름뿐 아니라 주요 실패 경로를 검토한다.
- 정책 결정과 기술 결정을 분리한다.
- 구현 단위와 검증 기준을 연결한다.
- 변경·빌드·생성·테스트 실행 없이 착수 판단과 다음 행동만 보고한다. 읽기·검색·로컬 상태 조회는 검토 범위에 포함한다.
