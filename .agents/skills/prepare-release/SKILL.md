# 릴리스 준비 검토

변경이 다음 단계로 넘어갈 준비가 되었는지 증거로 판단한다. 테스트 실패나 고위험 이슈를 숨기지 않고, 외부 변경 권한을 하나의 포괄적 승인으로 합치지 않는다.

## 기준 확인

1. 저장소 루트의 `AGENTS.md`를 먼저 읽고 명령, 테스트와 외부 변경 권한을 확인한다.
2. `docs/planning/role-structure.md`의 현재 역할 호출명, 인계, 완료 게이트와 사용자 승인 항목을 확인한다.
3. `docs/development/execution-playbook-design.md` 6절에 따라 프로젝트 식별자 또는 공통, 기준 문서, 대상 작업 경로와 참조 버전 또는 확인일을 식별한다. 목표·범위·요구사항·완료 기준은 `docs/product-planning.md`와 연결된 대상 문서에서 확인한다. 여러 아이디어를 관리하도록 정의된 경우에만 지정된 아이디어 문서와 인덱스를 사용한다.
4. 관련 개발·테스트·보고 문서와 `docs/development/execution-playbook-design.md`의 PB-06을 확인한다.
5. 코드 저장소가 있으면 대상 변경, 기준 브랜치, 작업 트리와 원격 상태를 확인한다.

## 권한 분리

다음 항목을 각각 독립적으로 확인한다.

| 권한 | 예시 | 승인되지 않은 경우 |
|---|---|---|
| 읽기·준비 검토 | 파일 읽기·검색, diff, 문서, 기존 테스트 결과, 설정과 로컬 상태 조회 | 기본 수행 |
| 명령 실행 | 포맷, 빌드, 생성, 설치, 상태 변경 명령 | 명령과 예상 결과만 제시 |
| 테스트 실행 | 단위, 통합, 브라우저, 회귀 테스트 | 기존 결과만 검토하고 미검증 표시 |
| 문서·코드 변경 | 릴리스 보완, 문서 갱신, 버그 수정 | 필요한 변경만 제안 |
| 커밋 | 로컬 커밋 생성 | 승인 필요로 표시 |
| 푸시 | 원격 브랜치 변경 | 승인 필요로 표시 |
| PR | PR 생성·수정 | 승인 필요로 표시 |
| 병합 | 기준 브랜치 반영 | 승인 필요로 표시 |
| 배포 | 스테이징·운영 환경 변경 | 승인 필요로 표시 |

- "릴리스 준비해줘"는 읽기·준비 검토 승인으로 해석한다.
- "테스트하고 PR 올려줘"는 테스트 실행과 PR 생성만 명시된 것으로 해석하고 커밋·푸시·병합·배포를 자동 포함하지 않는다.
- 필요한 선행 외부 변경이 승인되지 않았으면 해당 단계에서 멈추고 승인 항목을 보고한다.

## 준비 검토 절차

1. 릴리스 대상 변경, 관련 기능 ID, 포함·제외·보류 항목을 정리한다.
2. 요구사항과 실제 변경 파일, 완료 기준과 테스트 결과를 연결한다.
3. 필수 테스트의 실행 여부, 환경, 결과와 미실행 사유를 확인한다.
4. 실패 테스트, 보완 필요 발견 사항과 미해결 이슈의 심각도·영향·수용 여부를 확인한다.
5. 사용자, 개발, 운영, API와 데이터 문서의 갱신 필요성을 확인한다.
6. 환경 변수, 비밀값, 기능 플래그, 데이터 마이그레이션과 하위 호환성을 검토한다.
7. 롤백 방법, 배포 후 관찰 지표, 오류 확인과 책임자를 검토한다.
8. 승인된 명령과 테스트만 실행하고 결과를 준비 판단에 반영한다.
9. 승인된 외부 변경은 선행 조건을 다시 확인한 뒤 한 단계씩 수행하고 결과를 읽어 확인한다.
10. `준비 완료`, `조건부 준비`, `보류` 중 하나로 판단한다.

## 차단 기준

다음 항목은 별도 사용자 수용 없이 준비 완료로 표시하지 않는다.

- 승인된 필수 테스트의 실패
- 데이터 손상, 권한 우회, 민감 정보 노출 또는 복구 불가능 위험
- 적용 방법이나 롤백 방법이 없는 데이터·설정 변경
- 요구사항과 구현 범위의 중대한 불일치
- 영향과 대응 계획이 없는 고위험 미해결 이슈
- 필요한 외부 변경 권한 또는 실행 환경 부재

## 출력 형식

역할 문서에서 확인한 현재 호출명을 첫 줄에 표시하고 아래 순서로 작성한다.

1. 릴리스 대상과 제외 범위
2. 승인된 작업과 승인 필요 작업
3. 요구사항·변경·테스트 추적 결과
4. 문서·설정·데이터·롤백 점검
5. 미해결 이슈와 수용 상태
6. 준비 판단과 차단 사유
7. 다음 외부 변경과 담당 역할

점검 항목은 다음 필드를 사용한다.

| 필드 | 내용 |
|---|---|
| ID | `RELEASE-001` 형식 |
| 영역 | 범위, 테스트, 문서, 설정, 데이터, 롤백, 관찰, 외부 변경 |
| 상태 | 충족, 조건부, 미충족, 미검증, 적용 제외 |
| 근거 | 기능 ID, 파일, 테스트 결과, 이슈 |
| 영향 | 출시·운영 영향 |
| 필요한 조치 | 담당, 승인과 다음 행동 |

## 완료 조건

- 요구사항, 변경, 테스트와 이슈를 연결한다.
- 실행하지 않은 검증을 통과로 표시하지 않는다.
- 외부 변경 권한을 항목별로 구분한다.
- 준비 판단과 차단 사유, 다음 행동을 명확히 보고한다.
