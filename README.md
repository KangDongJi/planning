# 프로젝트 운영 기본 구조

새 프로젝트 또는 아이디어를 이미 이관받은 프로젝트에 역할 운영 체계를 적용하기 위한 기본 파일 묶음이다.

- 준비일: 2026-09-14
- 배치 위치: `~/projects/planning`
- 원본 출처: 장바구니 인큐베이션 워크스페이스의 공통 문서·플레이북·스킬
- 포함 범위: 직책 기반 책임, 호출명 관리, 승인 유지, 리뷰·수정 인계, 대상 기준 식별, 읽기·실행 구분
- 포함 범위 보완: 병렬 배정·통합 조건, 검토 독립성, 의견 충돌 처리, 작업 기록·재개 절차
- 포함하지 않은 범위: 개별 아이디어·제품 코드·과거 승인 및 테스트 통과 기록, 병렬 실행이나 외부 변경의 포괄 승인

## 새 프로젝트에서 사용

1. 새 프로젝트 루트에 AGENTS.md, docs/, .agents/skills/를 복사한다. 숨김 폴더 .agents도 포함한다.
2. docs/product-planning.md를 실제 프로젝트의 목표·범위·요구사항·완료 기준으로 채운다. 이 초안은 승인된 제품 기획서가 아니다.
3. 이관된 자료가 있으면 필요한 기획·조사·설계·검증 근거를 연결하고, 과거 사실과 현재 승인 범위를 구분한다.
4. AGENTS.md의 승인 규칙을 확인하고 프로젝트별 기술·실행·테스트 제약을 필요한 만큼 추가한다.
5. 새 프로젝트에서 역할 호출, 기준 문서 참조, 스킬 발견과 대표 요청 처리 방식을 확인한다.
6. 준비가 끝나면 승인된 범위의 실제 작업을 시작한다.

이미 이관된 프로젝트에는 기존 AGENTS.md·기획서·동일 이름 스킬을 덮어쓰지 않는다. 비교 후 공통 규칙과 누락 항목만 통합하며 docs/product-planning.md는 기존 기획서를 유지한다.

호출명을 바꾸려면 docs/planning/role-structure.md의 역할 목록에서 변경한다. 책임·절차는 직책명으로 유지한다. 사용자 전역 도구·플러그인·스킬은 이 묶음에 포함되지 않으므로 대상 환경에서 가용성을 확인한다.

## 시작 요청 예시

> PM 팀장, 이 프로젝트의 AGENTS.md와 기획서, 이관 자료를 확인해줘. 운영 문서·스킬의 누락과 충돌을 검토하고 다음 작업을 정리해줘. 아직 구현은 시작하지 마.

## 갱신

이 폴더를 공통 기본 구조 배포본으로 사용할 수 있다. 수정할 때는 변경 범위와 확인 결과를 기록하고, 다른 프로젝트에는 사용자가 지정한 범위에서 반영한다. 기존 프로젝트의 정책과 승인 이력을 기본값으로 대체하지 않는다.
